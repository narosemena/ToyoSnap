ToyoSnap — Corporate Policy Requirements Summary
(as applicable to this project)
1. Generative AI Use (Corporate Generative AI Policy)
What the policy explicitly requires:
Use of Generative AI must be reported and inventoried through the Corporate GenAI Intake process for any GenAI use beyond trivial querying, regardless of risk level.
Independent validation is mandatory for any work product created using GenAI. Outputs may be inaccurate or infringe intellectual property, and responsibility for validation rests with the user.
Company Confidential Information (which explicitly includes computer code) must not be entered into public GenAI tools.

How this applies to ToyoSnap

GenAI usage has been disclosed.
It has been asserted and documented that no Corporate data, code, systems, processes, or confidential information were entered into the GenAI tool.
Even with zero Corporate data involved, reporting and disclosure are still required, because the policy is inventory‑driven rather than harm‑driven.

✅ Required actions

Submit a GenAI Intake entry describing the use (inventory + governance visibility).
Document independent validation (tests, reviews) for the codebase.


2. Software Development Security (Secure Development Policy)
What the policy explicitly requires
The Secure Development policy establishes the Corporation’s baseline for secure software development, aligned to industry secure‑by‑design standards.
Key explicit requirements relevant here:

Secure SDLC artifacts are required, including documented security requirements and architecture considerations (for example, a Solution Architecture Document).
Source code must be managed in approved corporate systems with least‑privilege access controls.
The SDLC toolchain must support:

Source code management
Static Application Security Testing (SAST)
Software Composition Analysis (SCA) / SBOM
Dynamic testing where applicable
Coordination with the Corporate security engineering function is expected for centralized tracking.


Approval is required to use Open‑Source Software (OSS), and OSS use must comply with license terms and Corporate acceptable‑use standards.
Use of AI/LLMs in software development is subject to approval, and generated code must be reviewed and verified.

How this applies to ToyoSnap

ToyoSnap is software intended for potential Corporate use → secure development policy applies.
The project demonstrates explicit security intent via a zero‑egress architecture and enforcement tests, which supports—but does not replace—formal documentation.
The dependency footprint triggers OSS governance and SCA/SBOM expectations.

✅ Required actions

Maintain code in corporate‑approved source control.
Produce minimal but sufficient architecture and security documentation.
Produce an OSS dependency inventory with license awareness.
Validate GenAI‑assisted code via tests and review.


3. Open Source Software & Legal Considerations
What policy and internal guidance explicitly require

OSS usage requires approval and must comply with license terms.
Legal support for OSS licensing and compliance is available through designated Corporate legal advisory channels.

How this applies to ToyoSnap

OSS may be used.
OSS use must be documented, licensed correctly, and reviewed where necessary.
License ambiguity must be escalated to Corporate legal support—not assumed.

✅ Required actions

Maintain an OSS dependency and license list.
Escalate non‑obvious or restrictive licenses for legal review.


4. Source Control & Internal Systems
What internal guidance explicitly allows

The Corporation operates approved internal source control platforms with defined provisioning and access‑management processes.

How this applies to ToyoSnap

Corporate source control is an approved system of record for internal code.
Migration into Corporate systems is appropriate after governance hygiene (GenAI disclosure, OSS awareness, validation) is complete.

✅ Required actions

Create and maintain the repository within approved Corporate source control.


5. Policy Handling & Distribution Constraints
What is explicitly required

Corporate security and technology policies are classified as Confidential.
Documentation should link to official policy library sources, not reproduce policy text verbatim unless explicitly authorized.

How this applies to ToyoSnap

Project documentation may reference policies by link.
Policy text should not be copied into repositories or general documentation.

✅ Required actions

Reference policies via links only.


Consolidated Requirement Matrix (Plain English)
You must:

Report GenAI usage via the Corporate intake process.
Disclose and independently validate GenAI‑assisted code.
Store code in approved Corporate source control.
Document core architecture and security intent.
Track and govern OSS dependencies and licenses.

You must not:

Enter Corporate confidential information into public GenAI tools.
Treat OSS licensing as implicit or undocumented.
Reproduce confidential policy text outside approved repositories.

You are explicitly allowed to:

Bring in independently developed, GenAI‑assisted code with no Corporate data involved, provided disclosure and validation occur.
Use OSS in accordance with license and approval requirements.
Use approved Corporate source control and documentation platforms
