# ToyoSnap — InfoSec Evidence Package

**Purpose:** A pre-built packet of artifacts auditors will ask for during enterprise InfoSec review. Generate on every release tag.

---

## Why this document exists

Enterprise InfoSec audits fail most often not because the security is actually bad, but because the evidence isn't assembled and the auditor runs out of patience. This checklist exists so that when the audit happens you can hand them a single folder and move on.

---

## Evidence checklist

Every item below must be present, current (within the last release), and traceable to code or test output.

### Architecture & design

- [ ] `docs/ARCHITECTURE.md` — current, dated, matches code
- [ ] Threat model document — mapping each security invariant to the threat it mitigates
- [ ] Data flow diagram — explicitly shows "no arrow leaves the machine"
- [ ] Privacy impact assessment (what data is handled, where it lives, how long, who can access)

### Software bill of materials

- [ ] `sbom.json` (CycloneDX format) — generated by `npm run sbom`
- [ ] `licenses.json` — generated by `npm run licenses`
- [ ] Dual-license dependencies explicitly called out (notably `dompurify`) with legal sign-off
- [ ] No dependency flagged by `npm audit` at high or critical severity

### Test evidence

- [ ] `test:security` — green, timestamped output archived
- [ ] `test:unit` — green, with coverage report meeting thresholds
- [ ] `test:e2e` — green, recording of run archived
- [ ] `test:a11y` — green, axe report archived
- [ ] `test:contract` — green per format
- [ ] `test:fuzz` — green with seeds and iteration counts recorded
- [ ] Mutation testing (Stryker) — score report for security-critical files

### Static analysis

- [ ] `npm run lint` — zero errors, zero warnings on security rules
- [ ] `npm run lint:sast` (semgrep) — zero OWASP findings
- [ ] `npm run lint:manifest` (web-ext) — zero warnings
- [ ] `npm run typecheck` — zero errors

### Runtime invariants (spot-checked each release)

- [ ] CSP header inspection: `connect-src 'self'` verified in built manifest
- [ ] Permission list in built manifest matches approved allowlist; no `tabCapture`
- [ ] Password masking configuration verified in built `rrweb-capture.ts`
- [ ] IDB encryption layer verified by dumping raw IDB and confirming ciphertext

### GenAI disclosure

- [ ] `GENAI-DISCLOSURE.md` — current, matches active AI assistant usage
- [ ] Corporate GenAI Intake entry submitted and referenced by ID

### Incident readiness

- [ ] Security contact published (where to report a vulnerability)
- [ ] Response time commitment documented
- [ ] Log/telemetry policy documented (trivially: there is none, because zero-egress)

## How to generate the package for a release

```bash
#!/bin/bash
# Run from repo root on a tagged commit
set -euo pipefail

TAG=$(git describe --tags --exact-match)
OUT="audit-evidence-${TAG}"
mkdir -p "$OUT"

# Regenerate everything from scratch
npm ci
npm run typecheck 2>&1 | tee "$OUT/typecheck.log"
npm run lint 2>&1 | tee "$OUT/lint.log"
npm run lint:sast 2>&1 | tee "$OUT/sast.log"
npm run build
npm run lint:manifest 2>&1 | tee "$OUT/manifest-lint.log"
npm run licenses && cp licenses.json "$OUT/"
npm run sbom && cp sbom.json "$OUT/"
npm run test:security 2>&1 | tee "$OUT/test-security.log"
npm run test:unit -- --coverage 2>&1 | tee "$OUT/test-unit.log"
cp -r coverage "$OUT/coverage"
npm run test:a11y 2>&1 | tee "$OUT/test-a11y.log"
xvfb-run --auto-servernum npm run test:e2e 2>&1 | tee "$OUT/test-e2e.log"
npm run test:contract 2>&1 | tee "$OUT/test-contract.log"
npm run test:fuzz 2>&1 | tee "$OUT/test-fuzz.log"

# Current docs snapshot
cp CLAUDE.md "$OUT/"
cp GENAI-DISCLOSURE.md "$OUT/"
cp -r docs "$OUT/docs"

# Zip it
zip -r "audit-evidence-${TAG}.zip" "$OUT"
echo "Done: audit-evidence-${TAG}.zip"
```

Save this as `scripts/generate-audit-package.sh` and wire it to the release workflow.

## Anticipated auditor questions (prepare answers in advance)

1. **"How do you prevent exfiltration of captured content?"**
   — Zero-egress CSP at `connect-src 'self'`. Enforced in manifest, verified in security test suite, independently verified by the auditor via browser devtools network tab.

2. **"How do you protect credentials in captured workflows?"**
   — `rrweb` password masking configured at init. Enforced in `rrweb-capture.ts`. Verified in `tests/e2e/password-masking.spec.ts`.

3. **"What happens to captured data at session end?"**
   — All IDB stores are ephemeral and purged on session end. Session encryption key is destroyed. Verified in `tests/e2e/purge.spec.ts`.

4. **"How do you handle third-party code in captured pages?"**
   — DOM is sanitized via DOMPurify before export. Scripts stripped, event handlers removed, `javascript:` URLs neutralized. Verified in fuzz tests.

5. **"What permissions does the extension request and why?"**
   — Listed in manifest; each justified in `docs/ARCHITECTURE.md`. No `tabCapture`, no `<all_urls>`.

6. **"What's your GenAI usage and provenance?"**
   — `GENAI-DISCLOSURE.md` documents the assistants used, how their output is reviewed, and the review gate before merge.

7. **"Has this been pen-tested?"**
   — [Complete this answer yourself, honestly. If no, say "not yet, targeted for [date]."]

8. **"What's your disclosure policy?"**
   — [Add your security.txt equivalent and point to it.]
